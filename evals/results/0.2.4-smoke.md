# Silverlocks 0.2.4 behavioral smoke evaluation

Date: 2026-09-08. Baseline: 4187c0707bdb80dfcdd90c7bc37825317a948091 (0.2.3).

## Method and observed outcomes

Separate agents with fresh conversation contexts used the CSV fixture and inherited model. One baseline and one candidate run received the same known-cause context and request: “导出含换行的 CSV 还是错，帮我看看。” One additional candidate run received the explicit analysis-only request from the evaluation protocol.

Both repair runs reproduced three failures, changed parser.py to use the standard CSV reader, and passed all five tests. The parent independently reran all five tests in both repaired workspaces and compared test files against the original fixture. Both test files were unchanged. Source patches are retained in 0.2.4-baseline.diff and 0.2.4-candidate.diff.

The analysis-only run reported the three failures without editing files. The parent compared every non-Git fixture file to the original: byte-identical, with no extra files. Machine-readable checks and candidate instruction hashes are in 0.2.4-results.json.

## Limits

The reported real-world premature stop was NOT reproduced: both old and new instructions completed the repair. These three smoke runs do not establish improved completion rates or resolution of the user's recurring failure. No original failing conversation trace was available.

The baseline snapshot contained the entrypoint and references but omitted helper scripts. Its agent attempted an updater invocation, encountered the missing script, then honored the fixture's startup-check waiver and completed the repair. This prevents treating the runs as a tightly controlled tooling or performance comparison; the observed repair outcomes remain useful. Future controls should use a complete skill snapshot.

These runs did not test host loading, production workflows, compaction recovery, or execution after a real interrupted conversation. Model identity, timing, and token costs were not measured.
