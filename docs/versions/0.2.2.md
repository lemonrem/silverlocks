# Silverlocks 0.2.2

Date: 2026-09-07
Base revision: `2920f9a`.

## Outcome

Put action intent and completion criteria before workflow sizing. Contextual defect reports request repair without requiring another imperative. When a necessary authorized next action exists, execute it before ending the task. Preserve explicit analysis-only requests, assessment boundaries, safe retries, and concrete missing-access or decision blockers.

The earlier continuation fix was committed at version 0.2.1. Since the updater requires a strictly higher version, older installations did not automatically apply that same-version commit. Version 0.2.2 makes both corrections eligible for distribution. After a successful update, instructions now require rereading the entrypoint and changed references already used by the task.

## Scope and verification

Changed `SKILL.md`, `agents/openai.yaml`, `references/updates.md`, bilingual READMEs, `CHANGELOG.md`, and `VERSION`. No business repository, service, updater implementation, or user configuration changes.

- All 20 Python unittest cases passed, including updater fast-forward, rejection, cache, and continuity checks.
- Skill-creator `quick_validate.py` passed using an isolated uv dependency environment.
- Git whitespace validation passed.
- An independent agent received only the skill, an isolated Python shopping-cart fixture, and a natural-language defect report. It reproduced two failing cases, changed the calculation to account for quantity, and passed all three tests without requesting renewed permission. The resulting implementation was inspected. This single scenario is evidence of behavior, not a guarantee for all models or tasks.
- Local discovery inspection found one Silverlocks installation in the normal user skill roots and no explicit Silverlocks override in `skills.config`.

## Recovery

Revert the instruction and metadata changes if behavior regresses. To distribute a rollback through the updater, publish restored content with a higher patch version; lowering `VERSION` will not propagate automatically. Preserve dirty installations and workspace state. No application or database rollback is needed.

This record belongs to the source commit containing version 0.2.2. Update eligibility still depends on a clean trusted main checkout, fast-forward history, and the existing check interval.
