# Silverlocks 0.1.0 recovery record

Date: 2026-09-04

## Objective

Publish Silverlocks as a repository-independent, hook-free Codex Skill with complete installation and operating documentation.

## Outcome

- The repository root is directly installable as a personal Codex Skill.
- Development requests can load Silverlocks implicitly, while explicit `$silverlocks` invocation remains available.
- Direct and Plan Gate workflows scale process to task risk.
- Continuity uses a bounded, replace-only `.silverlocks/CURRENT.md` snapshot and intentional archives.
- Git commits and releases require tracked Markdown recovery records.
- English and Simplified Chinese documentation covers installation, updates, behavior, privacy, and validation.

## Decisions and constraints

- No plugin manifest, Hook, daemon, MCP server, background process, network call, or telemetry is included.
- Specialist Skills remain independently available and are never suppressed by Silverlocks.
- Workspace-local instructions and explicit user authority remain higher priority.
- The state namespace is `.silverlocks` to avoid collisions with Goldilocks installations.

## Components

- `SKILL.md` and `agents/openai.yaml`
- `references/continuity.md`
- `references/planning-and-verification.md`
- `scripts/continuity.py`
- `tests/test_continuity.py`
- `README.md`, `README.zh-CN.md`, `CHANGELOG.md`, `LICENSE`, and `NOTICE.md`

## Verification

- Five focused continuity helper unit tests passed.
- Python syntax compilation passed for the helper and its tests.
- `SKILL.md` frontmatter and `agents/openai.yaml` parsed successfully; the skill name, description, and implicit invocation policy were verified.
- The official validator's equivalent naming, frontmatter, key, length, and placeholder constraints were checked. Its bundled script could not start directly because PyYAML is absent from the host Python environment.
- The repository scan found no scaffold placeholders, private workspace paths, deployment endpoints, or project-specific references.

## Recovery

The initial repository commit is the recovery point for this version. To remove the workflow from a local Codex installation, disable its `SKILL.md` in `~/.codex/config.toml` or remove the installed Skill directory. No workspace state is deleted automatically.
