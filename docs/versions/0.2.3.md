# Silverlocks 0.2.3

Date: 2026-09-08. Base revision: `f2ca861`.

## Outcome and decisions

Adapt Goldilocks 0.6.1's evidence-driven diagnosis, failed-hypothesis memory, execution return points, and coherent ownership to the standalone Silverlocks skill. Consolidate repetitive execution rules: the entrypoint shrank from 9,224 to 5,094 bytes (44.8%), with diagnosis and handoff detail loaded only when relevant.

Recurring defects retain disproven approaches and a next distinguishing experiment. Status questions return to pending execution; explanation alone does not close authorized work. Reassessment remains the agent's responsibility when useful investigation is possible. Explicit diagnosis-only requests remain read-only. Repository-defined current-state files take precedence over a parallel Silverlocks snapshot.

No Hooks, background continuation loops, fixed model routing, forced delegation, or route receipts were added. The continuity schema and helper scripts are unchanged; existing `.silverlocks` installations require no migration. Repositories with their own state convention use that workflow without silently moving files.

## Changed surfaces

`SKILL.md`, planning/verification and continuity references, bilingual READMEs, provenance notice, changelog, and VERSION. Added isolated CSV behavioral fixtures, evaluation protocol, input hashes, a result summary, and the observed repair diff. No business project or user configuration changed.

## Verification

- All 20 existing Python helper tests passed.
- Skill-creator format validation and Git whitespace checks passed.
- Independent recurring-defect execution completed the repair and reused the existing debug note after a scheduled status question, without renewed user authorization. The evaluator inspected the patch and independently passed five immutable tests.
- Independent diagnosis-only execution left all fixture files byte-identical; the evaluator verified this against the baseline.
- Exact scope and measurement limits are in [the behavioral report](../../evals/results/0.2.3-smoke.md). There was no matched control arm, real cross-compaction recovery test, or completion-rate benchmark.

## Recovery

Restore prior instruction content if behavior regresses. Preserve repository-owned continuity files and user changes. To distribute a rollback automatically, publish restored content with a higher patch VERSION rather than lowering the version or resetting dirty installations. No application or database rollback is required. The source commit containing this record is the 0.2.3 distribution revision.
