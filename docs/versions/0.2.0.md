# Silverlocks 0.2.0 recovery record

Date: 2026-09-04

Base revision: `1ba88f3a5f59e69153e014d55583a0a86da66193`

## Objective

Improve Silverlocks as a safe, repository-independent development workflow and let Git-installed copies detect and apply published GitHub versions without reintroducing Hooks or background processes.

## Outcome

- A new conversation's first development task can run one update check; a successful check is cached for 24 hours and a network failure for one hour.
- Only a higher `VERSION` from the trusted `lemonrem/silverlocks` origin can update a clean `main` checkout through a fast-forward.
- Non-Git installs, local changes, untrusted origins, diverged history, invalid remote content, and network failures are preserved and reported without blocking the user's development task.
- Continuity reads and writes reject unsafe symlink paths and malformed bodies.
- Quoted objectives round-trip correctly, and invalid or oversized replacements no longer archive or remove the valid current snapshot first.
- The core Skill now states a concise inspect–implement–verify loop while preserving local repository rules, user changes, specialist Skills, and proportional testing.

## Decisions and constraints

- No Hook, daemon, scheduler, login item, plugin dependency, MCP server, or telemetry was added.
- Automatic checks occur only when Silverlocks is selected for a development task and never more than once per successful 24-hour cache window.
- The updater modifies only its own clean Git checkout and Git metadata. It never modifies the active business repository.
- Remote commits with an unchanged or lower `VERSION` are not applied automatically.
- Existing installations older than `0.2.0`, or installations copied without `.git`, require one manual update or reinstall before auto-update is available.
- Codex normally detects local Skill changes; after an applied update, one restart is recommended only when immediate adoption of new instructions must be certain.

## Verification

- Python compilation completed for both helper scripts.
- The focused unit suite covers continuity behavior plus clean fast-forward updates, copied installs, dirty working trees, diverged history, trusted origins, and the 24-hour cache.
- The Skill frontmatter, `agents/openai.yaml`, local Markdown links, balanced code fences, and Git whitespace are validated before commit.
- The bundled `quick_validate.py` could not start because the host does not provide its optional PyYAML dependency; no package was installed solely for this check, and the equivalent local metadata validation was run with the available YAML parser.

## Recovery

Revert the commit containing this record to return to the prior manual-update behavior. Existing project `.silverlocks` state remains untouched. If a local installation has already fast-forwarded to `0.2.0`, check out or reinstall the desired earlier trusted revision; do not reset a dirty installation without first preserving its local changes.
